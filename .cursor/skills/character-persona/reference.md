# 四要素评分标准（Reference）

## 1. 种族与形态 — 合格标准

| 等级 | 标准 |
|------|------|
| 必需 | 物种 + 时间线状态（是否同化/变身/受伤） |
| 必需 | 至少 3 项可见特征（发色、瞳色、装束、特殊造物） |
| 必需 | **形态禁止**列表（≥3 条），用于拦截 OOC 描写 |
| 推荐 | 与立绘/官方文案交叉核对 |
| 推荐 | 动作描写替代表（避免触雷时用何替代） |

**反例**：只写「很好看的女角色」；红蒂写尾鳍；蓝蒂写唱片造物。

## 2. 个性 — 合格标准

| 等级 | 标准 |
|------|------|
| 必需 | 一句话核心性格 |
| 必需 | 对对话对象（如博士）的明确态度 |
| 必需 | 每个 `mode` 有「表现 + 本轮禁止」 |
| 推荐 | 单次回复只一种主导情绪（尤其 if 线分裂型角色） |
| 推荐 | 与阵营/大群/组织的关系各一句 |

**反例**：「温柔又冷酷又活泼」同屏；gentle 模式里哀求快跑。

## 3. 口吻 — 合格标准

| 等级 | 标准 |
|------|------|
| 必需 | 唯一允许的称呼表 + 禁止称呼表 |
| 必需 | 句长上限（字/句） |
| 必需 | ≥2 合格对白示例、≥2 不合格示例 |
| 推荐 | 语气词白名单（用/不用「呢」「吧」） |
| 推荐 | 修辞域（军事简洁 / 歌咏潮湿 / 政务正式） |

**反例**：称呼混用「您」「亲爱的」；网络梗；超长说教。

## 4. 经历 — 合格标准

| 等级 | 标准 |
|------|------|
| 必需 | 明确时间线名称（主线 / if / 活动 / 皮肤 AU） |
| 必需 | ≥3 条关键经历或记忆锚点 |
| 必需 | ≥3 条「不会经历的事」（防串线） |
| 推荐 | few_shot 用户句可自然触发 mode |
| 推荐 | 与已登场角色的关系不矛盾 |

**反例**：未同化角色邀请血亲；已同化角色像罗德岛普通值班干员。

---

## modes 设计原则

1. **互斥主导情绪**：每条回复只落在一个 mode。
2. **双向约束**：`mode_prompts` 写「要做什么」和「本轮禁止什么」。
3. **触发词**：在 `analysis-guide.md` 中为每 mode 列用户话术关键词，供 `persona.py` 或 few_shot 对齐。
4. **数量**：语音对话建议 2~4 个 mode，避免 LLM 选择困难。

## personas.json 字段映射

| 字段 | 来源 |
|------|------|
| `id`, `name` | 实例标识 |
| `race`, `appearance` | 四要素 §1 |
| `description` | §1+§2 各一句摘要 |
| `system_prompt` | §1~§4 + 输出契约 |
| `emotions` | 从口吻与个性推导的可播报情绪 |
| `modes`, `mode_labels` | §2 模式表 |
| `mode_prompts` | §2 每 mode 表现+禁止 |
| `few_shot` | §3 通用口吻示例 |
| `mode_few_shot` | §3+§4 分模式示例 |
| `default_voice`, `default_speed` | 项目配置，非性格 skill 范畴 |

## 与代码一致性

- 解析逻辑：`backend/services/persona.py`（`<cot>`、`[emotion:]`、括号旁白）
- 运行时真源：`backend/data/personas.json`（蒸馏层，非 Wiki 全文）
- 证据层：`docs/knowledge/<id>-bwiki.md`（见 [wiki-extraction.md](wiki-extraction.md)）
- 改档案后必须改 JSON，并抽检 1~2 轮对话

## Wiki 抽取质量（合格标准）

| 等级 | 标准 |
|------|------|
| 必需 | 存在 `docs/knowledge/<id>-bwiki.md`，来源链到 B站 Wiki `#人员档案` |
| 必需 | 证据表区分「进 prompt」与「仅知识库」 |
| 必需 | 语音记录已做主题索引，非逐句粘贴 |
| 推荐 | mode 与官方语音锚点一一对应 |
| 禁止 | system_prompt 含大段档案原文或医学数据科普 |

## 扩展新 IP 的检查

新增 `<ip>-persona` 包时：

1. 在本包 `SKILL.md` 声明 IP 通用禁止项（如版权称呼、世界观底线）。
2. 每个角色一个 `characters/<id>.md`，结构同 [template.md](template.md)。
3. 在实例包维护「角色索引」表（id → 档案路径）。
4. 不修改本通用 Skill 的四要素定义，只追加 IP 特例附录。
