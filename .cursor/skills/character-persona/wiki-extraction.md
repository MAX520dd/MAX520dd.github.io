# 从官方 Wiki 抽取人设 — 规则

本文件规定：**新增或修订可对话角色时，必须先从官方 Wiki 抽取事实，再蒸馏为四要素与 `personas.json`**。  
Wiki 是**校对护栏与素材库**，不是每轮对话的 system prompt 全文。

---

## 1. 源站优先级

| 优先级 | 来源 | 用途 |
|--------|------|------|
| **P0** | [明日方舟 B站 Wiki](https://wiki.biligame.com/arknights/) 干员页 **#人员档案** | 基础档案、客观履历、临床诊断、档案资料、语音记录 |
| **P1** | 同页 **模组故事 / 干员密录**（若有） | 经历与意象；标注为「背景神话」，勿当日常对白背诵 |
| **P2** | [中文维基百科·明日方舟](https://zh.wikipedia.org/wiki/明日方舟) | **仅**泰拉世界观、阵营时间线；见 `docs/arknights-world-setting.md` |
| **P3** | 社区二次解读、梗图、同人文 | **不得**作为人设真源；与 P0 冲突时以 P0 为准 |

**禁止**：未标注出处的推断写入 `system_prompt`；把 Wiki 全文粘贴进 `personas.json`。

---

## 2. 必抓 Wiki 区块（按顺序）

干员页 URL 模式：`https://wiki.biligame.com/arknights/<干员名>`

| Wiki 区块 | 抽取内容 | 映射四要素 |
|-----------|----------|------------|
| **基础档案** | 专精、战斗经验、出身、生日、身高、矿石病 | §1 种族与形态、§4 经历 |
| **客观履历** | 职位、所属、过往任务类型 | §4 经历 |
| **招聘合同 / 信物** | 一句气质、象征物 | §2 个性意象、§3 口吻隐喻 |
| **临床诊断 / 综合体检测** | 感染状况、源石适性、异常体征 | §1 形态边界（医学事实，口语中不科普） |
| **档案资料 一~四**（信赖解锁） | 人际关系、战斗方式、心理动机 | §2 个性、§4 经历 |
| **语音记录** | 任命助理、交谈、信赖、作战、失败等 | §3 口吻、§2 mode 锚点 |

### 语音记录用法

- 按**主题**归纳（距离感、同伴、作战、睡眠……），不要逐句塞进 prompt。
- 每条语音最多提炼 **1 个气质关键词 + 1 条短示例** 进入 `few_shot` 或 mode 说明。
- 游戏内「Dr.博士」等称呼，按本项目契约统一为 **「博士」**（可在知识库保留原文并注明改写）。

---

## 3. 同页混杂内容（明日方舟常见）

B站 Wiki 个别页面会收录**其他时间线/形态**的档案（例如浊心页含主线斯卡蒂信赖档案）。

处理规则：

1. 只录入与**当前实例 id** 对应时间线的段落。
2. 若段落明确描写另一形态（如「斯卡蒂小姐」「试试当正常干员」属主线），记入知识库 **§背景参考（非本实例日常）**。
3. 四要素与 `system_prompt` **不得**混用另一形态的台词与动机。

---

## 4. 产出物（固定路径）

每新增一个 `personas.json` 角色，**必须**完成两层落盘：

```
docs/knowledge/<id>-bwiki.md     # Wiki 摘录知识库（证据层）
.cursor/skills/<pack>/characters/<id>.md   # 四要素蒸馏（执行层）
backend/data/personas.json         # 运行时真源（压缩层）
```

### 4.1 知识库 `docs/knowledge/<id>-bwiki.md`

必备结构：

```markdown
# <角色名> · 人员档案知识库（B站 Wiki 摘录）

> **来源**：<Wiki URL>#人员档案
> **用途**：校对与 OOC 审查；不注入每轮对话
> **录入**：<日期>

## 1. 基础档案
## 2. 临床/综合体（若有）
## 3. 档案资料摘要（表格）
## 4. 语音气质（主题索引表）
## 5. 对话还原要点（从官方 → 口语，禁止科普腔）
## 6. 关联文件
```

### 4.2 角色档案 `characters/<id>.md`

在模板顶部链回知识库；四要素写**蒸馏后**的可执行规则，不复制 Wiki 长文。

### 4.3 `personas.json`

`system_prompt` 只保留：**身份 + 形态禁止 + 性格锚点 + 口吻契约 + 输出格式**。  
长度建议 ≤ 单条中文 400~600 字；细节留在知识库与 `characters/<id>.md`。

---

## 5. 证据表（抽取时必填）

分析阶段在 `characters/<id>.md` 或 PR 说明中附表：

```markdown
| 事实 | Wiki 区块 | 用于四要素 | 是否写入 system_prompt |
|------|-----------|------------|------------------------|
| 非感染者 | 基础档案 | §1 | 是（一句） |
| 行动失败「快逃」 | 语音记录 | plead mode | 是（锚点） |
| 信赖150% 凯尔希长段 | 档案资料 | 背景 only | 否 |
```

规则：

- **写入 system_prompt**：高频口吻、硬边界、mode 锚点、形态禁止。
- **仅知识库**：长档案、医学数据、未解锁信赖全文。
- **禁止写入任何地方**：其他干员专属设定、地球现代梗、与 P0 矛盾的社区谣言。

---

## 6. 自然融入原则（与世界观文档一致）

从 Wiki 抽取是为了 **防 OOC**，不是为了 **念设定**：

- 日常对白**零**档案科普（不说「我的体细胞融合率为 0%」）。
- 官方意象（干燥/潮湿、歌谱、两米距离）**在相关话题出现时**口语化带出。
- 不把 `docs/knowledge/*.md` 全文注入 `build_system_prompt()`。

---

## 7. 抽取工作流（与 character-persona 衔接）

```
1. 打开 P0 Wiki #人员档案 → 抓取/整理
2. 写 docs/knowledge/<id>-bwiki.md（证据层）
3. 填 evidence 表 → 推导四要素
4. 写 characters/<id>.md（执行层）
5. 压缩同步 personas.json
6. 实例包 SKILL.md「角色索引」增加一行（档案 + 知识库链接）
7. 自检：文末检查表 + 与易混角色硬边界
```
